# ExternalPeepSight 项目实施计划

## 1. 文档目的

本文定义 ExternalPeepSight 从当前工程骨架到首个可发布版本的实施顺序、阶段交付物、质量门禁和完成标准。

计划基线日期为 2026 年 7 月 23 日。当前仓库已经具备：

- .NET 10 与 C++20 工程骨架；
- Core、UI、Host 和测试项目；
- 严格的托管与原生质量检查；
- 需求规格说明和技术实现方案；
- VisibilityRule 的初始实现与测试；
- 待迁移的 WPF UI 骨架。

目标 UI 技术栈为 Avalonia 12.1.0、FluentAvaloniaUI 3.0.2 和 MVVM。覆盖引擎继续使用 C++20、Win32、Direct3D 11、Direct2D 与 DirectComposition。

## 2. 实施原则

### 2.1 高风险能力优先

完整 UI 开发前必须先验证：

- 覆盖窗口是否可靠置顶；
- 鼠标和键盘是否完全穿透；
- DirectComposition 路线在目标游戏中是否可用；
- 多显示器、不同 DPI 和负坐标是否正确；
- 前台窗口变化时是否能可靠切换目标显示器；
- 静止覆盖是否能满足 CPU 和内存目标。

这些能力决定 Host 的窗口和渲染路线。原型未通过时，不继续堆叠配置管理和完整视觉界面。

### 2.2 领域逻辑与平台代码分离

- 可确定计算、校验、配置合并和版本迁移放入 Core。
- Win32、DirectX、Raw Input 和进程生命周期放入 Host。
- Avalonia 项目只负责界面、预览和用户操作编排。
- C# 与 C++ 不能共享的协议逻辑通过版本化规范、JSON Schema、Golden Fixtures 和等价测试保持一致。

### 2.3 每个阶段均可验证

每个阶段必须：

- 产生可运行或可测试的交付物；
- 达到明确的退出标准；
- 通过对应的质量门禁；
- 不依赖未实现页面掩盖底层缺陷；
- 保持提交范围小且可审查。

## 5. 阶段 1：覆盖引擎技术原型

### 5.1 工作内容

1. 为每个选中显示器创建独立覆盖 HWND。
2. 应用 `WS_EX_TOPMOST`、`WS_EX_TOOLWINDOW`、`WS_EX_NOACTIVATE` 和点击穿透策略。
3. 初始化 D3D11、Direct2D、DirectComposition 和交换链。
4. 绘制静态中心点、四支臂和透明 PNG。
5. 处理不同 DPI、负坐标、主屏切换和显示器拔插。
6. 使用前台窗口决定焦点显示器，鼠标位置作为回退。
7. 验证鼠标按键、滚轮和键盘输入不被覆盖窗口截获。
8. 记录 CPU、私有工作集、Present 延迟和设备重建表现。

### 5.2 技术决策门

至少在以下环境验证 DirectComposition 路线：

- Windows 10 和 Windows 11；
- 单屏和不同 DPI 的双屏；
- DX11、DX12 和 Vulkan；
- 窗口化、无边框和 Fullscreen Optimizations；
- 普通 DPI 和高 DPI；
- 主屏位于右侧以及存在负虚拟坐标。

原型使用 `WS_EX_LAYERED`、整窗 alpha 与 DirectComposition 组合，并通过运行时命中测试确认跨进程点击穿透。Windows 11 实测确认，全显示器透明 HWND 会改变半透明任务栏的后景合成；窗口技术路线因此确定为按实际视觉内容包围盒创建小尺寸 HWND，坐标计算仍以完整显示器为基准。阶段 6 增加图像和 Toast 时必须动态重算包围盒，并在内容分离较远时拆分窗口，不能恢复为包含大面积透明空白的全屏窗口。

### 5.3 退出标准

- 覆盖内容在目标显示模式中稳定可见；
- 覆盖窗口不激活、不抢焦点且不阻断输入；
- 多显示器切换无明显残影；
- 设备资源能够销毁和重建；
- 已形成可重复的手工兼容性矩阵；
- 点击穿透和层级路线已经确定；
- `.\check.ps1 -Coverage -Deep` 通过。

## 6. 阶段 2：领域模型与配置契约

### 6.1 Core 模型

实现以下领域对象和值类型，并区分单个配置、配置库状态和应用设置：

- Profile 与 ProfileSet，其中 Profile 只承载准星、逻辑开关及其快捷键，并为动画及动画快捷键预留扩展；
- Crosshair、CenterPoint 和 Arm；
- ImageOverlay 与 AssetReference；
- SwitchConfiguration 与 VisibilityRule；
- HotkeyBinding 与 KeyIdentity；
- 独立于 Profile 的 ProfileSet 成员关系和当前选择状态；
- 独立于 Profile 的 MonitorSelection；
- ToastConfiguration；
- 坐标、像素、角度、缩放和持续时间值。

主题、语言、窗口状态、显示器策略、Toast、配置集关系和配置切换快捷键不得成为单个 Profile 的字段。

单位必须体现在类型或成员名称中，例如 `offsetPx`、`angleDeg` 和 `durationMs`。

### 6.2 配置能力

- 版本化 JSON 序列化；
- 字段范围和资源引用校验；
- 配置版本迁移；
- 临时文件写入和原子替换；
- `.bak` 恢复；
- 300 ms 防抖保存；
- `.epsx` 导入导出；
- ZIP 路径穿越、大小、数量和压缩炸弹防护；
- GUID、同名配置和资源冲突合并；
- 导入失败整体回滚。

### 6.3 跨语言契约

在独立契约目录维护：

```text
contracts/
  ipc/
  configuration/
  fixtures/
```

契约目录包含消息示例、配置示例、非法输入样例和 C#/C++ 共用的期望结果。不能依靠复制注释维持两端一致。

### 6.4 退出标准

- 所有公开 Core API 具有 XML 文档；
- 模型、校验、迁移和合并规则均有单元测试；
- 无效输入、边界值和失败回滚均被覆盖；
- Core 行覆盖率和分支覆盖率均不低于 85%；
- `.\check.ps1 -Coverage` 通过。

## 8. 阶段 4：IPC 与进程生命周期

### 8.1 工作内容

- 版本化 Named Pipe JSON 消息；
- `PIPE_REJECT_REMOTE_CLIENTS`；
- 当前用户 ACL；
- 随机 Pipe 名、握手 Token 和单实例互斥量；
- 消息大小、JSON 深度和字段范围限制；
- `requestId`、配置版本和 Ack/Error；
- UI 启动 Host、连接、断开和重连；
- 区分 Host 正常退出与异常退出，正常退出不会被 UI 自动拉起；
- Host 状态重新同步；
- UI 关闭后 Host 继续运行；
- Host 托盘菜单提供打开设置和退出命令。

### 8.2 退出标准

- 正常连接、重复连接和断线重连测试通过；
- 过大、损坏、未知版本和乱序消息被拒绝；
- 旧版本不能覆盖新版本；
- 非当前用户或未通过握手的客户端不能发送命令；
- UI 和 Host 任意一方异常退出后可以恢复到明确状态。

- Toggle、独立开关键和 Hold 状态机；
- 按键自动重复过滤；
- 左右修饰键、扩展键和数字区区分；

- 后端去重和注册失败回滚；
- 快捷键冲突与系统保留组合校验。

### 9.2 退出标准

- 三种激活方式的状态转换测试完整；
- 同一物理按键不会被两个后端重复触发；

- 冲突信息包含具体按键和错误原因；

## 10. 阶段 6：完整渲染能力

### 10.1 工作内容

- 中心点颜色、半径和可见性；
- 四支臂同步和独立编辑；
- 角度、间隔、长度、宽度和颜色；
- PNG 解码、尺寸限制和纹理缓存；
- 静态 SVG 校验、解码和外部引用拒绝；
- 图像定位、缩放和宽高比；
- Toast 字体、位置、持续时间、优先级和合并；
- 约 16 ms 的热重载更新合并；
- 设备丢失后的资源缓存重建。

### 10.2 退出标准

- C# 预览几何与 C++ 渲染几何通过相同 Golden Fixtures；
- 连续滑块修改不会让旧快照覆盖新快照；
- 图片不在每次绘制时重新解码；
- 非法 PNG、SVG 和资源引用被安全拒绝；
- 静止覆盖满足 CPU 和内存目标。

### 10.3 实施结果

阶段 6 使用 `contracts/fixtures/render-geometry-v1.json` 同时验证 C# 预览纯函数和 C++ Host 几何。Host 在发布新快照前完成资源路径、大小、SHA-256、PNG IHDR、SVG XML 和 Direct2D 文档预构建；失败不会覆盖上一份有效配置。

PNG 通过 WIC 解码，SVG 通过 Direct2D SVG 文档绘制。缓存以资源 SHA-256 为身份，静止绘制和每帧绘制均不重新读取或解码文件；设备丢失后按同一不可变快照重建缓存。准星、图像与 Toast 使用按实际内容计算的独立小尺寸 HWND，不恢复全屏透明窗口。

UI 侧 `QueueSnapshotAsync` 将连续编辑合并到约 16 ms 一个批次，只发送批次内最新版本。`ShowToast` 支持优先级、去重键、默认或单条持续时间，并通过独立内容窗口绘制。详细验证见 `docs/阶段6验证记录.md`。

FluentAvalonia 作为唯一主题。七个页面均通过同一个配置工作区修改不可变

## 13. 质量门禁

根据改动风险执行项目级 Quality Gate：

| 改动类型 | 必须执行 |
|---|---|
| 纯文档 | `git diff --check` |
| 普通 Avalonia UI、私有重构 | `.\check.ps1` |
| Core 行为、配置、序列化和校验 | `.\check.ps1 -Coverage` |
| Win32、DirectX、输入、IPC、线程和构建脚本 | `.\check.ps1 -Coverage -Deep` |
| 发布候选版本 | `.\check.ps1 -Coverage -Deep` 加完整手工矩阵 |

任何阶段不得通过降低警告、分析器、覆盖率、安全审计或原生检查标准来满足门禁。

## 14. 提交策略

每个提交只包含一个可说明、可验证的行为边界。推荐按以下粒度提交：

- UI 框架迁移；
- UI Headless 测试基础设施；
- 覆盖窗口创建；
- D3D/D2D/DirectComposition 初始化；
- 显示器拓扑；
- Core 数据模型；
- 配置校验与持久化；
- IPC 协议；
- Raw Input 状态机；
- 各个 UI 功能页；
- 兼容性和发布配置。

不要把 UI、Host、协议和配置模型的大规模变化压入同一个提交。提交前执行该改动所需的最高等级质量门禁。

## 15. 开发前必须定稿的产品决策

以下项目应在对应功能进入实现前写入需求文档：

1. 中心点是否只支持圆形，以及半径范围；
2. 四个支臂是否分别保存间隔；
3. 开关 A/B 的启动默认状态；
4. 焦点屏幕以活动窗口还是鼠标为主；
5. 全部屏幕模式下是否复用相同的显示器本地坐标；
6. 图像超出屏幕后裁剪还是隐藏；
7. 字体不存在时的回退顺序；
8. 配置同名冲突是否自动添加名称后缀；
9. SVG 文件大小、尺寸、节点数和嵌套深度限制；
10. 是否在首个版本支持开机启动。

未定稿内容不得由 UI、Core 和 Host 分别采用不同默认值。默认值必须由配置契约统一定义。
