## 2. 实现结果

### 2.1 输入线程与后端选择

- Input 线程拥有独立隐藏 HWND，并在该线程上创建和释放 Raw Input、WTS 会话通知、低级键盘钩子和系统热键。
- 无修饰键的 Toggle/独立开关键以及所有 Hold 绑定进入 Raw Input 后端。
- 带修饰键的 Toggle/独立开关键进入 `RegisterHotKey`，并使用 `MOD_NOREPEAT`。
- Raw Input 使用 `RIDEV_INPUTSINK | RIDEV_DEVNOTIFY`；注册失败时才启用 `WH_KEYBOARD_LL`，两个键盘捕获后端不会同时工作。
- 输入回调只更新状态机并通过轻量窗口消息发布结果，不执行渲染、IPC 或文件操作。

### 2.2 状态机与恢复

- `KeyIdentity` 使用扫描码、扩展位和修饰键掩码匹配。
- 同一物理键保持按下时忽略重复 KeyDown。
- Hold 的 KeyUp 按物理键释放，因此先松开修饰键不会导致 Hold 卡住。
- Raw Input 设备移除、WTS 会话变化和 Input 线程关闭会清空已按键并释放活动 Hold。
- 新配置成功应用后恢复配置中的 A/B 初始状态，并重新计算 `SwitchA`、`SwitchB`、`Both` 或 `Either` 可见性。

### 2.3 配置热重载与失败处理

- `ApplySnapshot` 在推进 IPC 配置版本前解析并应用 `switches`。
- 非法输入配置返回 `InvalidInputConfiguration`，系统热键注册失败返回 `InputRegistrationFailed`。
- 注册失败信息包含扫描码、扩展位、修饰键掩码和 Win32 错误号。
- 新 `RegisterHotKey` 计划失败时恢复旧计划；回滚本身失败时清理全部系统热键并将输入状态标记为未配置。
- 验证或注册失败不会推进 Host 的配置版本；相同版本和内容的幂等重放不会重复应用配置。
- 第一份有效 IPC 配置到达前，覆盖层保持原型既有可见行为；之后显示器选择结果与逻辑开关可见性共同决定覆盖窗口是否显示。

### 2.4 冲突和保留键校验

Core 与 Host 均拒绝：

- 与激活模式无关或缺失的按键字段；
- A/B 开关有效动作之间重复的完整 `KeyIdentity`；
- 含 Win 修饰键的组合；
- 左右 Windows 主键；
- Alt+Tab、Alt+Esc、Ctrl+Esc、Ctrl+Alt+Delete；
- F12 调试器保留键；
- 无法转换为系统虚拟键的 `RegisterHotKey` 组合。
