# 外置准星软件需求规格说明书

## 1. 引言

### 1.1 项目背景与目的
本项目旨在开发一款适用于 Windows 平台的外置准星辅助软件。它能够在屏幕最前端叠加自定义的准星或图像，尤其适用于各类全屏、窗口化游戏中缺乏原生准星或需要自定义准星的场景。软件需具备高度可定制性、灵活的热键控制、多屏幕兼容以及配置的持久化与共享能力。

### 1.2 适用范围
本需求文档详细描述了外置准星软件的全部功能需求、非功能需求及约束条件，供开发、测试和项目管理人员使用。

### 1.3 术语与缩写
- **准星**：由中心点与四个支臂组成的十字形叠加元素。
- **支臂**：构成准星的四个方向线段，位置由角度和间隔定义。
- **逻辑开关**：控制准星显示与否的虚拟开关，可映射至键盘快捷键。
- **显示控制级别**：控制准星显示与隐藏的功能级别，分为基础、进阶和高级。
- **变量**：进阶级别中由用户定义并在运行时维护的布尔、整数或双精度浮点值。
- **动作**：由按键事件、变量条件或脚本触发的可执行操作。
- **按键事件**：全局按键或鼠标按键的按下事件和松开事件。
- **脚本**：高级级别中由用户编写、在受限 Lua 环境中执行的控制程序。
- **脚本作用域**：脚本能够读取和控制的产品对象范围，分为配置级、配置集级和全局级。
- **脚本绑定槽位**：脚本声明、由用户在 UI 中选择实际键盘或鼠标按键的稳定输入入口。
- **脚本设置项**：脚本声明、由用户在 UI 中修改并由 Host 校验和持久化的类型化参数。
- **配置**：一条可独立保存、切换和共享的运行方案。除名称、标识符和 schema 版本等必要元数据外，只包含准星配置、当前显示控制级别及其配置级控制内容，以及未来的动画配置和动画快捷键配置。
- **配置集**：多个配置的集合，用于快速切换。
- **应用设置**：不属于单个配置的全局行为，包括显示器选择、提示样式、界面主题、界面语言和其他运行环境偏好。

## 2. 总体描述

### 2.1 运行环境
- 操作系统：Windows 10/11 及更新版本（支持 x64 架构）。
- 配置界面：C#、.NET 10、Avalonia 12 Desktop、FluentAvalonia 3.x、MVVM 架构。
- 覆盖引擎：C++20、Win32、Direct3D 11、Direct2D、DirectWrite、WIC 与 DirectComposition。
- 进程通信：配置界面与覆盖引擎通过 Windows Named Pipe 通信。
- 硬件要求：支持多显示器，分辨率无强制限制。

### 2.2 用户特征
面向需要精确自定义准星的游戏玩家，期望软件能穿透游戏界面置顶显示，且快捷键操作灵活，不影响游戏体验。

### 2.3 设计约束
- 覆盖引擎必须创建半透明、无焦点、始终置顶且点击穿透的窗口，不能干扰游戏操作。
- 支持窗口化、无边框窗口、窗口化全屏、无边框全屏和 Windows Fullscreen Optimizations 下的覆盖显示。
- 不支持并不承诺覆盖 DirectX 9/10/11 的真正独占全屏（Fullscreen Exclusive）模式；DirectX 12 不存在真正独占全屏模式。
- 不使用游戏进程注入、内核驱动、内存读写或输入模拟实现覆盖和热键功能。
- 默认不以管理员权限运行。热键功能采用 Raw Input、系统热键和低级键盘钩子的分层策略；用户可显式启用“管理员输入兼容模式”，仅以管理员权限重启 Host，设置 UI 继续保持普通权限。
- 配置界面虽然使用跨平台 UI 框架，但产品仍以 Windows 10/11 x64 为唯一受支持平台，不因采用 Avalonia 扩大本期平台范围。
- 配置界面统一使用 FluentAvalonia 提供的主题和扩展控件，不与 `Avalonia.Themes.Fluent` 同时注册，避免基础样式和资源键冲突。
- Avalonia 官方包必须保持相同版本；FluentAvalonia 固定到经过验证的 3.x 版本，不使用浮动版本。

### 2.4 进程与数据架构
- 软件由配置界面进程和覆盖引擎进程组成。覆盖引擎负责覆盖窗口、渲染、显示器拓扑、热键、逻辑开关、变量、动作和脚本运行时状态。
- 配置界面负责参数编辑、预览、配置管理和导入导出。设置界面关闭后，覆盖引擎可继续在后台运行。
- 两个进程通过本地 Named Pipe 传递版本化 JSON 消息。配置与应用设置使用彼此独立的版本化数据契约，图片资源由覆盖引擎缓存为纹理。
- 配置界面采用 `.resx` 资源文件，预留中文和英文的本地化能力。

## 3. 功能需求

### 3.1 模式管理
**FR-01 模式切换**
系统提供两种叠加模式：自定义准星模式和自定义图像模式，用户可在主界面任意切换。

#### 3.1.1 自定义准星模式
**FR-02 准星整体位置**
允许用户通过拖拽或坐标输入设定准星在屏幕上的整体偏移位置（相对于屏幕中心或绝对坐标）。

**FR-03 中心点控制**
- 提供“显示中心点”开关，默认开启。
- 允许自定义中心点颜色（支持颜色选择器/十六进制值输入）。

**FR-04 准星支臂配置**
支臂参数支持独立修改与同步修改（默认同步）：
- **支臂角度/间隔**：四个支臂相对于十字基准线的旋转角度或间隔角度（例如 0°, 90°, 180°, 270° 可整体旋转偏移）。
- **支臂宽度**：支臂线条的粗细（像素）。
- **支臂长度**：支臂从中心点向外延伸的长度（像素）。
- **支臂颜色**：支持颜色选择，独立或统一设置。

**同步/独立修改机制**：提供“链接”按钮或勾选框，激活时四个支臂参数同步变化；取消后可分别调整每个支臂。

#### 3.1.2 自定义图像模式
**FR-05 图像导入**
允许用户从本地文件系统上传 PNG 或 SVG 格式图片作为叠加图像。

**FR-06 图像位置**
允许设置图像在屏幕上的显示位置，支持坐标输入或屏幕区域拖拽定位（基准点可选图像中心或左上角）。

**FR-07 图像缩放**
提供缩放比例调节（滑块或数值输入），保持宽高比或允许自由拉伸。

### 3.2 多屏幕支持
**FR-08 屏幕选择**
- 系统自动枚举所有连接的显示器。
- 用户可指定在全部屏幕、特定几个屏幕或仅当前焦点屏幕（鼠标/活动窗口所在屏幕）上显示准星。
- 当选择“焦点屏幕”时，准星跟随活动窗口所在屏幕自动切换。

### 3.3 游戏覆盖兼容性
**FR-09 覆盖层级保障**
- 软件必须创建最顶层、无焦点、点击穿透的窗口（WS_EX_TOPMOST, WS_EX_TRANSPARENT, WS_EX_NOACTIVATE）。
- 每个选中显示器创建独立覆盖窗口，并在显示器拓扑、DPI 或焦点屏幕变化时及时更新位置和尺寸。
- 使用 Direct3D 11、Direct2D 与 DirectComposition 渲染和合成覆盖内容；不得使用 GDI 持续重绘实现准星渲染。
- 在窗口化、无边框窗口和 Windows Fullscreen Optimizations 模式下，确保准星渲染于游戏画面之上。真正独占全屏模式不在支持范围内。

### 3.4 准星显示控制与快捷键
**FR-10 显示控制级别**
系统提供三种准星显示与隐藏控制级别，用户可以在配置中选择其中一种：

1. **基础**：使用两个固定逻辑开关和现有的显示规则控制准星。
2. **进阶**：移除逻辑开关概念，使用用户定义的变量、按键事件和动作控制准星及配置。
3. **高级**：使用用户编写的 Lua 脚本控制准星显示、隐藏和配置切换。

同一配置只能启用一个显示控制级别。切换级别时，系统必须保留其他级别的已编辑内容，但只执行当前选中级别的控制逻辑。

基础级别已经实现，作为现有产品基线继续维护。下一阶段直接实现高级级别的 Lua 脚本能力；进阶级别的变量和动作编排暂不实现，保留为更后续版本需求。配置契约可以为进阶级别预留版本字段，但当前不得写入 Host 无法完整校验和执行的私有字段。

#### 3.4.1 基础级别
**FR-11 基础级别逻辑开关**
基础级别保持现有逻辑，系统内置两个逻辑开关：开关 A 和开关 B。准星实际显示条件为用户定义的逻辑组合：

- 仅开关 A 开启时显示；
- 仅开关 B 开启时显示；
- 开关 A 与开关 B 同时开启时显示；
- 任意一个开关开启时显示（A 或 B）。

**FR-12 基础级别快捷键绑定**
每个逻辑开关支持三种激活方式，用户可独立配置：

- **独立开关键**：分别为“开启”和“关闭”分配不同键位；
- **单一开关键**：同一个键位在“开启”与“关闭”状态间切换；
- **长按激活**：按下并保持时开关为开启状态，松开后自动转为关闭状态。

基础级别允许绑定键盘按键和鼠标按键。按键重复、按键释放丢失、输入设备移除、锁屏和会话切换必须按照统一输入状态机处理。

#### 3.4.2 进阶级别
**FR-13 进阶级别变量**
进阶级别不使用逻辑开关 A/B，改用用户定义的变量：

- 支持布尔类型；
- 支持 32 位或 64 位有符号整数类型，具体位宽由实现方案确定；
- 支持双精度浮点类型；
- 每个变量必须具有稳定标识符、显示名称、类型和默认值；
- 变量属于当前配置，配置切换时加载目标配置的变量定义和默认运行时状态；
- UI 必须提供变量的新增、修改、删除和类型查看能力；
- 删除仍被动作、条件或脚本引用的变量时，必须阻止删除并显示引用位置。

**FR-14 进阶级别按键事件**
用户可以为键盘或鼠标按键的以下事件绑定动作：

- 按下事件；
- 松开事件。

系统必须区分首次按下与自动重复按下。动作绑定必须明确触发条件、动作顺序和作用范围。

**FR-15 进阶级别动作**
当前支持的动作包括：

- 切换到指定配置；
- 切换到指定配置集；
- 切换到上一个配置或下一个配置；
- 切换到上一个配置集或下一个配置集；
- 设置准星显示或隐藏状态；
- 设置变量的值；
- 对变量执行数学运算；
- 对变量执行逻辑运算；
- 对变量执行条件判断；
- 当变量满足条件时执行指定动作，不满足时忽略该动作。

动作设计必须明确输入变量、目标类型、操作符、操作数和执行结果。类型不兼容、变量不存在、配置不存在或运算结果超出范围时，动作不得部分执行，并必须记录可供 UI 显示的错误。

**FR-16 进阶级别执行规则**

- 同一事件绑定多个动作时按稳定顺序执行；
- 一个动作失败时，是否继续执行后续动作必须由统一动作执行策略确定，不能由单个 UI 控件隐式决定；
- 条件动作可以嵌套，但必须设置最大嵌套深度；
- 动作不能无限递归触发自身或形成无界循环；
- 同一输入事件在一次事件处理周期内必须具有明确的去重规则；
- 变量更新、显示状态变化和配置切换必须在 Host 内以原子状态转换发布；
- 进阶级别最终输出统一的准星显示状态和配置切换请求，不直接操作渲染对象。

#### 3.4.3 高级级别
**FR-17 Lua 脚本作用域与控制**
高级级别允许用户编写 Lua 脚本。脚本分为以下三个作用域：

1. **配置级脚本**
   - 随所属配置激活和停止；
   - 可以控制当前配置是否允许显示；
   - 可以读取当前配置的只读上下文和配置级运行时状态；
   - 可以请求切换当前配置集内的指定、上一个或下一个配置；
   - 不能切换配置集，不能修改其他配置或全局应用设置。
2. **配置集级脚本**
   - 随所属配置集激活和停止；
   - 在同一配置集内切换配置时继续运行；
   - 可以控制当前配置集是否允许显示；
   - 可以读取当前配置集及当前配置的只读上下文；
   - 可以切换当前配置集内的配置；
   - 不能切换到其他配置集，不能修改全局应用设置。
3. **全局级脚本**
   - 随 Host 启动和停止；
   - 可以控制全局是否允许显示；
   - 可以读取当前配置、当前配置集和显示器状态的只读上下文；
   - 可以切换配置和配置集；
   - 默认关闭，必须由用户显式启用。

三个作用域只扩大脚本能够管理的产品对象范围，不增加操作系统权限。脚本不得直接访问内部配置对象、渲染对象、窗口句柄或 IPC 对象，必须通过版本化、白名单形式的脚本 API 执行操作。

高级级别下，每个作用域可以挂载并同时运行多份已启用脚本。每份脚本使用独立运行时，最终准星显示状态按所有活动脚本合并：

```text
visible =
    allGlobalScriptsAllowVisible
    && allProfileSetScriptsAllowVisible
    && allProfileScriptsAllowVisible
    && renderContentAvailable
```

任意脚本都不能突破其他脚本的隐藏决定。输入事件根据作用域、挂载脚本稳定标识符和绑定槽位精确路由到一份脚本，回调完成后重新合并全部活动脚本状态并发布渲染更新。

脚本切换配置或配置集时，旧作用域脚本必须在切换提交后停止接收新事件。脚本产生的切换、显示和变量动作进入统一事件队列，不能同步递归调用其他脚本。系统必须限制单次事件的动作数量、事件链深度和重复触发次数。

**FR-18 脚本按键绑定与设置注册**
脚本允许声明按键绑定槽位、可选默认物理按键和用户设置项，但不能在运行阶段直接注册具体物理按键或绕过 UI 修改用户绑定。

脚本绑定槽位必须声明：

- 稳定标识符和显示名称；
- 支持按下事件、松开事件或两者；
- 默认是否启用；
- 可选默认物理按键及修饰键；
- 所属脚本和作用域。

用户在 UI 中为绑定槽位选择键盘按键、鼠标按键或组合键。脚本运行时只接收绑定槽位标识符和按下/松开阶段，不读取用户实际绑定的物理键。所有活动脚本绑定必须与基础级绑定一起进入 Host 的统一输入计划，执行重复绑定、系统保留组合键和后端能力校验。任意绑定注册失败时必须继续使用上一份完整有效的输入计划，不能部分替换。

脚本设置项必须声明：

- 稳定标识符和显示名称；
- 类型、默认值和可选说明；
- 数值范围或固定选项集合；
- 所属脚本和作用域。

首期脚本设置类型允许布尔、整数、双精度浮点、字符串和固定选项。UI 根据类型生成开关、数值输入、文本输入或下拉选择控件。用户修改设置后，必须先经过 UI 和 Host 双重校验，再向脚本发布设置变化事件。

脚本源代码、用户按键绑定和用户设置值必须分开存储。脚本升级时按照稳定标识符迁移：

- 新增绑定声明优先采用脚本提供的默认物理按键；未提供时保持未绑定并等待用户设置；
- 删除声明后停止生效，但旧值进入可恢复的迁移数据；
- 修改显示名称不影响已有值；
- 修改同一标识符的类型视为不兼容变更，必须要求用户确认或重新配置；
- 修改绑定默认按键或设置默认值不得覆盖用户已经保存的值，用户主动清空绑定也视为已保存值；
- 新脚本声明无效时拒绝整份脚本更新并继续使用上一份有效版本。

**FR-18A Lua 执行安全**

- 禁止文件系统、网络、进程、注册表、动态库和系统 API 访问；
- 限制单次执行时间、指令数量、调用深度和内存使用；
- 脚本不能直接注册物理按键、修改自身源代码或创建未声明的持久化字段；
- 脚本异常、超时或超出资源限制时，Host 不得崩溃；
- 脚本失败时保留上一份有效显示状态、配置状态和输入计划；
- 脚本编辑器必须提供语法错误、声明错误和运行错误反馈；
- 导入配置或配置集时，必须对脚本大小、复杂度、声明内容和调用权限进行校验；
- 脚本不得绕过配置校验、输入冲突校验和配置版本校验。

**FR-18B 脚本管理与独立脚本库**

- 提供独立的脚本管理界面，按配置级、配置集级和全局级管理脚本；
- 脚本管理界面允许列出、创建、编辑、停用和移除当前配置、当前配置集或全局的多份已挂载脚本，并通过 Host 验证后整体应用；
- 提供不属于任何配置、配置集或全局运行状态的独立脚本库，脚本库至少保存稳定标识符、名称、目标作用域和 Lua 源码；
- 独立脚本库使用单独的本地持久化文件，不进入配置 JSON，也不随配置或配置集的 EPSX 导入导出；
- 用户可以将脚本库中的脚本追加复制到当前配置、当前配置集或全局；复制时必须按目标作用域重新验证权限和声明，不能覆盖已有挂载脚本；
- 用户可以把当前已挂载脚本复制回独立脚本库，后续修改脚本库副本不得自动修改原挂载脚本；
- 准星编辑的高级区域不提供源码、作用域、删除或脚本库管理控件，按脚本分组显示当前配置级脚本注册的设置、按键绑定和启用状态，并提供进入当前配置脚本管理界面的快捷入口；
- 用户在准星编辑高级区域修改注册设置或按键绑定后，修改必须进入正常配置校验和热重载流程。

**FR-18C 脚本声明式设置界面**

- 脚本 API v1 继续由程序根据设置类型自动生成设置界面，现有脚本无需迁移；
- 脚本 API v2 允许脚本为已声明设置提供受信任的界面元数据，包括显示顺序、分区、分区说明、单列或双列布局、折叠状态、控件类型、设置说明、单位、数值步长和简单条件显示；
- 首期白名单控件包括开关、复选框、滑块、数值输入、单行文本框、下拉选择和分段选择；控件必须与设置类型兼容；
- 自定义界面必须引用每个已声明设置且只能引用一次，不能创建未声明设置、隐藏未列出的持久化设置或绕过类型、范围和枚举校验；
- 条件显示只允许比较另一个已声明设置是否等于一个合法常量。条件只影响控件可见性，不能修改设置值或触发脚本动作；
- UI 声明与脚本源码、绑定声明和设置声明一起由 Host 解析并通过源码哈希绑定。持久化声明与源码不一致时拒绝整份配置；
- 脚本不得提供 AXAML、样式、模板、C# 控件类型、事件处理器、资源路径或可执行 UI 代码，不得在 UI 进程中运行 Lua；
- 脚本不能重排或隐藏应用导航、脚本管理、按键绑定、冲突提示、安全提示和其他系统拥有的界面。

#### 3.4.4 状态提示
**FR-19 状态提示文案**

- 基础级别允许为每个逻辑开关的开启和关闭动作自定义提示文字；
- 进阶和高级级别允许为配置切换、变量变化和脚本动作配置提示策略；
- 提示显示位置、持续时间、字体样式和优先级需可配置，未配置时使用默认半透明悬浮提示；
- 提示失败不得影响准星显示控制和配置切换。

### 3.5 配置与配置集管理
**FR-20 配置保存**
用户可将当前运行方案保存为一条持久化配置，存储至本地数据库或文件。配置必须包含用户自定义名称，并包含：

- 准星配置，其中同时保留自定义准星和图片准星参数，当前模式决定实际使用哪一套；
- 显示控制级别及对应的基础、进阶或高级控制内容；
- 基础级别的逻辑开关规则、初始状态和逻辑开关快捷键绑定；
- 进阶级别的变量定义、按键事件和动作绑定；
- 高级级别的配置级 Lua 脚本、脚本 API 版本、绑定槽位声明、设置项声明，以及该配置级脚本的用户绑定和设置值；
- 未来扩展的动画参数；
- 未来扩展的动画快捷键绑定。

除名称、标识符、schema 版本和图片资源引用等必要元数据外，单个配置不得包含其他内容。配置集级脚本、全局级脚本、显示器选择、提示样式、界面主题、界面语言、配置集归属、当前选中的配置或配置集，以及独立于脚本的全局配置切换快捷键均不属于单个配置。

**FR-21 配置集管理**
- 允许创建多套配置集，每个配置集可包含多个配置。
- 允许将某一配置分配到一个或多个配置集中。
- 提供配置集和配置的增、删、改、查界面。
- 高级级别下，配置集可以保存配置集级 Lua 脚本、脚本 API 版本、绑定槽位声明、设置项声明，以及用户为该脚本保存的绑定和设置值。
- 全局级 Lua 脚本及其用户绑定和设置值属于应用状态，不属于任何配置或配置集。

**FR-22 配置与配置集的导入/导出**
- 支持导出单个配置或整个配置集为外部文件（如 .json 或自定义格式）。
- 支持从文件导入配置或配置集到软件中，自动合并或新增。
- 导出单个配置时不得夹带应用设置或配置集成员关系；导出配置集时，配置集结构与其引用的配置分别存储。
- 导出单个配置时，应包含该配置的配置级脚本、声明、用户绑定和用户设置值。
- 导出配置集时，应包含该配置集的配置集级脚本、声明、用户绑定和用户设置值，以及成员配置各自的配置级脚本数据。
- 全局级脚本属于应用状态，不得默认随单个配置或配置集导出；只能通过独立的应用状态备份功能显式导出。
- 导入包含脚本的内容时，必须在启用前展示脚本作用域、声明的绑定槽位、设置项和请求使用的脚本 API。

**FR-23 快捷键切换**
- 允许用户指定快捷键：切换上一个/下一个配置集。
- 允许指定快捷键：在当前配置集内切换上一个/下一个配置。
- 切换时可叠加半透明文字提示当前配置/配置集名称。

### 3.6 热键系统特殊要求
**FR-24 全局热键输入捕获**
- 常规组合快捷键优先使用系统级 `RegisterHotKey` 注册。
- 单键、长按和按键释放状态优先使用 Raw Input 捕获，并使用低级键盘钩子和按键状态轮询作为冗余来源，确保远控软件截断部分输入路径或应用无焦点时仍能维护逻辑开关、动作和脚本绑定状态。
- 事件捕获与轮询必须分别维护物理键状态，只有合并状态发生变化时才驱动快捷键逻辑；轮询瞬时返回未按下时不得抵消仍处于按下状态的 Raw Input 或低级钩子来源。
- 低级键盘钩子（`SetWindowsHookEx`）仅作为兼容性回退方案，钩子回调不得执行耗时操作。
- 不使用 DirectInput、驱动级输入模拟或内核驱动绕过游戏输入与反作弊机制。
- 如远控软件或目标程序以管理员权限运行，可由用户主动启用管理员输入兼容模式。切换时必须通过已认证 IPC 退出旧 Host，再按目标完整性级别启动新 Host；取消 UAC 时不得重复弹窗。用户手动以管理员身份启动设置 UI 时，Host 必须沿用管理员权限，不得因默认普通权限偏好形成重复重启。该模式不保证任意游戏、驱动级输入或反作弊环境下的热键可用性。

### 3.7 热重载
**FR-25 热重载**
所有配置项（准星参数、图像、显示控制级别、逻辑开关、变量、动作、脚本，以及未来的动画与动画快捷键绑定）在通过界面修改后立即生效，无需重启软件或手动应用。配置修改失败时必须保留最近一次有效配置和运行状态。

## 4. 非功能需求

### 4.1 性能
- 准星静止时采用事件驱动渲染，不要求持续以显示器刷新率重复提交相同画面。参数修改、配置切换、提示显示和屏幕切换应在一个显示器刷新周期内反映到覆盖层。
- 在设置界面关闭、覆盖引擎后台运行的基准测试环境中，覆盖引擎 CPU 平均占用率低于 1%，私有工作集低于 50MB。
- 图像模式下，PNG/SVG 必须在导入或首次使用时解码并缓存为纹理，避免实时解码造成卡顿。
- SVG 导入仅支持安全的静态图形内容；必须拒绝脚本、外部资源引用、超出限制的尺寸或复杂度，以及不受渲染引擎支持的内容。
- 进阶动作和高级脚本必须使用事件驱动执行，不得通过高频轮询维持准星显示状态。
- Lua 脚本执行不能阻塞窗口、输入、IPC 或渲染线程；脚本执行时间和资源限制必须可测量。

### 4.2 兼容性
- 在窗口化、无边框窗口和 Windows Fullscreen Optimizations 模式下，支持运行 DirectX 9/10/11/12、Vulkan 或 OpenGL 的游戏覆盖显示；兼容性以显示模式而非游戏图形 API 为边界。
- 真正独占全屏模式不在支持范围内，软件不得通过注入、驱动或读写游戏进程内存扩展该范围。
- 不承诺任何反作弊系统均不会限制或标记本软件。软件必须保持透明窗口叠加、无注入、无驱动、无游戏进程内存访问，并建立主流游戏与反作弊版本的兼容性测试矩阵。

### 4.3 可用性
- 用户界面简洁，主要配置分类清晰。
- 支持多语言架构（至少预留英文/中文切换接口）。

### 4.4 安全性
- 导入配置文件时校验版本、格式、字段范围、文件大小和资源数量，防止代码执行、资源耗尽和配置损坏问题。
- 导入的图片与 SVG 文件必须进行类型、尺寸、复杂度和外部资源引用校验，不执行其中的脚本或外部引用。
- Lua 脚本必须运行在受限沙箱中，禁止访问文件系统、网络、进程、注册表、动态库和 Windows API。
- Lua 脚本必须设置执行时间、指令数量、调用深度、内存和脚本大小上限。
- 脚本异常、超时、资源耗尽或 API 调用失败时，必须保留上一份有效状态，不能导致 Host 进程崩溃。
- 软件自身不联网，不传输任何用户数据。

## 5. 界面原型要点（非完整设计，仅辅助说明）

- 主窗口分为模式选择区、准星预览区、参数调节面板（分组折叠）。
- 主窗口采用 FluentAvalonia 主题，支持浅色、深色和跟随系统三种主题模式。
- 参数编辑优先使用数值输入、滑块、颜色选择器、开关和分段选择等语义明确的控件，不能用自由文本输入替代具有范围约束的参数控件。
- 逻辑开关设置页以图形化表示开关状态与映射按键。
- 显示控制级别使用清晰的分段选择或选项卡；基础、进阶和高级级别的编辑区域必须互相区分。
- 进阶级别提供变量列表、变量类型和值编辑、按键事件编辑和动作编排界面，并显示变量引用和条件关系。
- 高级级别分别提供配置级、配置集级和全局级脚本入口，并明确显示脚本栈、作用域、生命周期和权限。
- 高级级别提供 Lua 编辑器、脚本 API 说明、语法错误、声明错误和运行错误提示，但不能以普通文本框替代结构化的安全设置。
- 脚本源码和脚本库管理集中在独立脚本管理页；准星编辑中的“高级”区域只显示当前配置脚本的注册设置、按键绑定、状态和快捷入口。
- UI 根据脚本声明生成按键捕获、设置编辑、冲突提示和默认值恢复控件；脚本不能隐藏或绕过这些用户可见的绑定和设置。
- API v2 脚本可以在白名单范围内声明设置分区、控件表现和简单条件显示；应用导航、源码管理、绑定编辑和安全反馈仍由程序固定控制。
- 配置集管理采用 `TreeView` 与 `DataGrid` 或 `ListBox` 组合，支持拖拽分配；不依赖需要 AGPL 或商业授权的 TreeDataGrid。
- 命令按钮优先使用 FluentAvalonia 自带图标；只有在图标覆盖不足时才增加一套统一的第三方图标库。

## 6. 验收标准

### 6.1 现有基础级别基线

1. 能在窗口化、无边框窗口和 Windows Fullscreen Optimizations 的 DirectX 12 游戏中稳定显示准星且不干扰游戏输入；真正独占全屏不在验收范围内。
2. 所有快捷键按配置生效，长按、切换逻辑正确，提示文字准确显示。
3. 配置导入导出无信息丢失，配置集切换流畅。
4. 热重载：拖动滑块改变支臂长度时，准星实时变化。
5. 多屏幕下焦点屏幕切换时准星跟随无残影。
6. 设置界面关闭后，覆盖引擎在基准测试环境中的 CPU 平均占用率低于 1%，私有工作集低于 50MB。
7. 覆盖、热键和配置切换不使用游戏进程注入、内核驱动或游戏进程内存访问。
8. 基础级别中，两个逻辑开关的按下、松开、切换、长按和显示规则行为与现有逻辑一致。

### 6.2 下一阶段高级级别验收

1. 配置级、配置集级和全局级脚本按照各自生命周期启动和停止，不能越过作用域修改其他对象。
2. 三个活动脚本作用域内的所有脚本显示决定按照逻辑与规则合并，任意脚本不能突破其他脚本的隐藏决定。
3. 脚本可以声明按键绑定槽位和类型化设置项，用户可以在 UI 中修改实际按键和设置值。
4. 脚本不能在运行阶段直接注册物理按键；绑定冲突或注册失败时继续使用上一份完整有效的输入计划。
5. 脚本升级时，稳定标识符未变化的用户绑定和设置可以保留；不兼容类型变化必须要求用户重新确认。
6. Lua 脚本可以通过受限 API 控制准星显示、隐藏和配置切换；脚本越权、异常、超时和资源超限均不能突破沙箱或破坏上一份有效状态。
7. 实现高级级别时不能破坏现有基础级别的配置迁移、热键行为和显示规则。
8. API v1 脚本继续使用自动设置界面；API v2 脚本可以声明受信任的设置布局和白名单控件，非法引用、类型不匹配和持久化声明篡改会被整体拒绝。

### 6.3 后续进阶级别验收

1. 布尔、整数和双精度浮点变量可以通过按键事件修改，并能驱动准星显示、隐藏和配置切换。
2. 变量条件不满足时条件动作不会执行；动作失败、类型错误和循环触发均有明确错误处理。
