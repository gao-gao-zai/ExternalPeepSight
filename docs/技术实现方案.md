# 外置准星技术实现方案

## 1. 文档目的

本文将《外置准星软件需求规格说明书》拆解为可以直接进入开发的模块、数据结构、Windows API 和测试要求。

实现目标是：

- 配置界面和覆盖引擎解耦；
- 正常运行时不注入游戏、不读取游戏进程、不安装驱动；
- 覆盖窗口不激活、不抢焦点、不接受鼠标操作；
- 参数修改能够在一个显示器刷新周期内同步到覆盖层；
- 配置、快捷键和显示器变化都具备可恢复的状态管理。

## 2. 总体架构

```text
ExternalPeepSight.UI.exe
  C# / .NET 10 / Avalonia 12 Desktop / FluentAvalonia 3.x / MVVM
  - 配置编辑
  - 预览
  - 配置集管理
  - 导入导出
  - 启动和连接 OverlayHost
             |
             | Windows Named Pipe
             | 版本化 JSON 消息
             v
ExternalPeepSight.Host.exe
  C++20 / Win32
  - 覆盖窗口
  - D3D11 / Direct2D / DirectComposition
  - 显示器拓扑
  - Raw Input / RegisterHotKey
  - 逻辑开关状态机
  - Toast 提示
```

### 2.1 进程职责

| 进程 | 负责内容 | 不能负责的内容 |
|---|---|---|
| UI | 编辑配置、校验输入、显示预览、导入导出 | 直接创建最终覆盖窗口、处理实时按键 |
| Host | 创建覆盖窗口、渲染、全局输入、显示器切换、热重载 | 修改配置文件、执行用户导入的内容 |

Host 在后台常驻。UI 关闭时，Host 继续显示当前准星。UI 重新打开时，通过 `Hello` 消息读取 Host 当前状态。

### 2.2 线程模型

Host 至少包含以下线程：

- **UI/Window 线程**：创建 HWND、处理窗口消息、`WM_DISPLAYCHANGE`、`WM_DPICHANGED`、窗口层级维护。
- **Input 线程**：创建接收 Raw Input 的隐藏窗口，处理按键消息并更新逻辑开关。
- **Render 线程**：维护 D3D11 设备、Direct2D 资源和每个显示器的交换链。
- **IPC 线程**：读取 UI 命令，校验并提交不可变配置快照。

线程之间不共享可变配置对象。UI、输入和渲染线程使用引用计数的 immutable snapshot；新快照提交成功后一次性替换指针，避免渲染过程中读取到半更新状态。

### 2.3 UI 技术栈与依赖边界

配置界面采用 Avalonia Desktop，首个实现基线为 Avalonia 12.1.0 与 FluentAvaloniaUI 3.0.2。所有 Avalonia 官方包必须锁定到相同版本，FluentAvalonia 必须锁定到已经通过项目检查的具体版本，不能使用浮动版本范围。升级任一基础 UI 包时，必须同步执行依赖审计、UI 启动测试和关键控件冒烟测试。

UI 层使用：

- `Avalonia.Desktop`：桌面应用生命周期、窗口和平台集成；
- `FluentAvaloniaUI`：唯一的应用主题和 Fluent 扩展控件来源；
- `CommunityToolkit.Mvvm`：属性通知、命令、校验和 ViewModel 基础设施；
- `Avalonia.Headless.XUnit`：无需真实桌面的控件与交互测试。

UI 已采用单一 `ConfigurationWorkspace` 作为编辑会话边界。页面 ViewModel 不直接维护可序列化
配置副本；每次有效修改都使用 record `with` 表达式生成新的完整文档，经
`ConfigurationValidator` 校验后再发布。工作区负责以下顺序：

1. 更新内存中的不可变文档；
2. 使用约 16 ms 合并窗口向 Host 发送递增版本的完整 JSON 快照；
3. 使用 300 ms 防抖和 `AtomicConfigurationStore` 保存本地配置；
4. Host 明确拒绝快照时恢复最近一次已确认文档，连接中断时保留本地编辑等待重连；
5. 重连后优先采用 Host 返回的较新快照和版本。

用户界面文本来自 `Strings.resx` 和 `Strings.zh-CN.resx`。切换语言时将当前 ResourceSet
重新发布到应用动态资源；主题通过 `RequestedThemeVariant` 在系统、浅色和深色之间切换，
不注册 `Avalonia.Themes.Fluent`。

应用只注册 `FluentAvaloniaTheme`，不得再注册 `Avalonia.Themes.Fluent`。页面和业务控件不得依赖 FluentAvalonia 的内部资源键、复制其内部控件模板或直接引用未公开类型，避免补丁版本升级造成不可控破坏。

首期不引入其他完整主题库、Docking、图表、富文本编辑器或 WebView。图标优先使用 FluentAvalonia 自带的 Symbol 图标；确认内置集合无法覆盖产品命令后，才允许增加一套统一的第三方图标库。

控件选择：

- 模式和视图切换使用导航、选项卡或分段选择控件；
- 数值参数使用带上下限的数值输入，并按需要配合滑块；
- 颜色使用颜色选择器并保留十六进制输入；
- 配置集使用 `TreeView`，配置列表使用 `DataGrid` 或 `ListBox`；
- 配置分配使用 Avalonia 拖放 API；
- 确认、冲突和导入结果使用 ContentDialog 或页面内信息提示；
- 不使用采用 AGPL 或商业授权的 TreeDataGrid。

UI 项目虽然采用 Avalonia，但只发布和测试 `win-x64`。窗口生命周期、托盘、单实例、文件选择器和系统主题检测都按 Windows 产品行为设计，不将 Linux 或 macOS 支持作为当前架构约束。

## 3. 核心数据模型

### 3.1 坐标和单位

- 配置文件中的位置、间隔、长度和宽度全部使用物理像素。
- Avalonia 界面使用 DIP，发送到 Host 前根据目标显示器 DPI 转换为物理像素。
- 默认坐标基准为目标显示器的完整边界，不使用工作区，避免任务栏改变准星位置。
- `CenterOffset` 表示相对于显示器中心的偏移。
- `AbsolutePosition` 表示相对于目标显示器左上角的坐标。
- 多显示器使用每个显示器自己的本地坐标，不能直接把一个虚拟桌面坐标复制到所有显示器。

### 3.2 配置模型

一条配置同时保存自定义准星和图片准星参数，`activeMode` 只决定当前显示哪一种，这样切换模式时不会丢失另一套参数。配置还保存逻辑开关规则、逻辑开关初始状态及其快捷键绑定，并为未来的动画参数和动画快捷键绑定预留版本化扩展位置。

配置的业务内容严格限制为：

- 自定义准星和图片准星；
- 逻辑开关及其快捷键；
- 未来的动画及其快捷键。

名称、稳定标识符和 schema 版本属于必要元数据。图片文件元数据可由图片准星引用，二进制资源仍独立存放。显示器策略、Toast、主题、语言、配置集成员关系、当前选择状态和配置切换快捷键属于独立的应用状态，不得序列化到单个配置中。

```json
{
  "schemaVersion": 3,
  "profiles": [
    {
      "id": "guid",
      "name": "Default",
      "activeMode": "crosshair",
      "crosshair": {
        "anchor": "screenCenter",
        "offsetPx": { "x": 0, "y": 0 },
        "center": {
          "visible": true,
          "color": "#FFFFFFFF",
          "radiusPx": 2
        },
        "arms": {
          "linked": true,
          "items": [
            {
              "angleDeg": 0,
              "gapPx": 6,
              "lengthPx": 12,
              "widthPx": 2,
              "color": "#FFFFFFFF",
              "visible": true
            }
          ]
        }
      },
      "image": {
        "assetId": "guid",
        "anchor": "screenCenter",
        "offsetPx": { "x": 0, "y": 0 },
        "scale": 1.0,
        "keepAspectRatio": true
      },
      "switches": {
        "visibilityRule": "switchA",
        "initialStateA": false,
        "initialStateB": false,
        "switchA": { "mode": "unbound" },
        "switchB": { "mode": "unbound" }
      },
      "animation": null
    }
  ]
}
```

配置集和应用设置使用独立文档：

```json
{
  "profileSets": [
    {
      "id": "guid",
      "name": "FPS",
      "profileIds": ["guid"]
    }
  ],
  "selectedProfileSetId": "guid",
  "selectedProfileId": "guid",
  "monitorSelection": { "mode": "focus" },
  "toasts": { "enabled": true }
}
```

### 3.3 角度模型

需求中的“支臂角度/间隔”应拆成两个字段：

- `angleDeg`：支臂方向，顺时针为正，0 度指向上方；
- `gapPx`：中心点到支臂起点的空隙；
- `lengthPx`：支臂线段长度；
- `widthPx`：支臂宽度。

支臂几何计算：

```text
direction = (sin(angle), -cos(angle))
start = center + direction * gapPx
end   = start   + direction * lengthPx
```

线帽、抗锯齿和像素对齐由 Direct2D 统一处理。宽度为奇数时根据目标 DPI 进行半像素对齐，避免准星发虚。

## 4. FR 实现映射

| 需求 | 实现方式 |
|---|---|
| FR-01 模式切换 | Profile 内保存两套视觉参数；Host 根据 `activeMode` 选择 CrosshairRenderer 或 ImageRenderer。切换只提交新快照。 |
| FR-02 整体位置 | UI 预览支持拖拽和坐标输入；Host 按 anchor、目标显示器边界和 DPI 计算物理像素位置。 |
| FR-03 中心点 | 使用 D2D 椭圆或小矩形绘制；颜色解析为 premultiplied BGRA；建议补充半径字段。 |
| FR-04 支臂 | 四个 Arm 统一走同一套几何计算；`linked=true` 时编辑器修改全部 Arm，`false` 时只修改当前 Arm。 |
| FR-05 图像导入 | UI 读取文件头和尺寸；PNG 使用 WIC 解码；SVG 使用 D2D SVG 文档，拒绝脚本、外部引用和超大内容。 |
| FR-06 图像位置 | ImageRenderer 使用图像中心或左上角作为 anchor；UI 的“定位模式”只修改配置，不让普通覆盖窗口接收鼠标。 |
| FR-07 图像缩放 | 缩放时保持原始资源不变，只改变绘制矩阵；保持比例时只允许统一缩放，自由拉伸时分别计算 X/Y。 |
| FR-08 屏幕选择 | Host 使用显示器枚举建立 MonitorDescriptor；全部屏幕创建多个 HWND，焦点屏幕只激活一个目标。 |
| FR-09 覆盖层 | 每个目标显示器创建独立 HWND；窗口按实际可见内容包围盒定位，D3D11 设备共享，交换链和 DirectComposition visual 按窗口独立维护。 |
| FR-10 开关 A/B | `SwitchState { A, B }` 只存在于 Host 内存中；程序启动默认关闭，避免启动后意外显示。 |
| FR-11 显示规则 | 纯函数计算 `visible = rule(A, B)`，规则枚举为 A、B、A_AND_B、A_OR_B。 |
| FR-12 快捷键 | 组合键用 RegisterHotKey；裸键、长按和释放用 Raw Input；每个绑定进入统一 KeyEvent 状态机。 |
| FR-13 提示 | Host 使用 DirectWrite 绘制 Toast；提示带过期时间和优先级，重复状态提示按 key 合并。 |
| FR-14 配置保存 | 以 GUID 标识 Profile；写临时文件、Flush、再原子替换正式文件；写入失败保留上一份有效配置。 |
| FR-15 配置集 | ProfileSet 只保存 Profile ID 列表，支持一个 Profile 被多个集合引用；删除 Profile 前检查引用并给出处理选项。 |
| FR-16 导入导出 | 使用带 `manifest.json` 和 `assets/` 的 `.epsx` ZIP 包；先解压到临时目录并完整校验，成功后再合并。 |
| FR-17 快速切换 | ProfileSet 和 Profile 内部都维护稳定顺序；上一项/下一项使用模运算；切换后发送 Toast。 |
| FR-18 输入捕获 | Raw Input 窗口放在 Host Input 线程；按键消息只投递轻量事件，不能在回调里做文件、IPC 或渲染操作。 |
| FR-19 热重载 | UI 每次修改生成配置版本号；Host 校验、构建资源并原子替换 snapshot；失败返回错误，不覆盖旧状态。 |

## 5. 覆盖窗口实现

### 5.1 HWND 属性

普通运行状态使用以下窗口属性：

- `WS_EX_TOPMOST`
- `WS_EX_TOOLWINDOW`
- `WS_EX_NOACTIVATE`
- `WS_EX_TRANSPARENT`
- `WS_EX_LAYERED`（与整窗 alpha 配合，提供跨进程点击穿透）
- `WS_EX_NOREDIRECTIONBITMAP`（DirectComposition 路线）

创建窗口后使用 `SetLayeredWindowAttributes(..., 255, LWA_ALPHA)` 保持整个窗口不透明度不变，同时让系统按 Layered Window 的规则跳过透明输入区域。使用 `SetWindowPos(HWND_TOPMOST, ..., SWP_NOACTIVATE | SWP_SHOWWINDOW)` 设置层级，不能调用会激活窗口的显示方式。

`WS_EX_TRANSPARENT` 不能单独当作点击穿透的设计保证；`HTTRANSPARENT` 也不能单独证明跨进程输入会继续传递。原型使用 `WS_EX_LAYERED` 与整窗 alpha，并必须验证：

1. 游戏窗口和 Host 不在同一线程；
2. DX9、DX11、DX12、Vulkan 和 OpenGL 的窗口化/无边框模式；
3. 多显示器和 HDR/高 DPI 环境；
4. 鼠标左键、右键、滚轮和侧键均不被覆盖窗口吞掉。

当游戏或其他 Topmost 窗口改变前台状态时，Host 在 `EVENT_SYSTEM_FOREGROUND` 回调后使用 `SetWindowPos` 重新确认覆盖窗口层级；该操作必须带 `SWP_NOACTIVATE`，不能通过周期性抢占窗口焦点维持层级。

覆盖窗口创建后禁用 DWM 非客户区渲染，避免系统为透明顶层窗口增加边框或阴影。Windows 11 实测表明，即使禁用该效果，全显示器透明 DirectComposition HWND 仍会改变半透明任务栏的后景合成，使任务栏可见地变暗。移除 `WS_EX_LAYERED` 或使用 `SetWindowRgn` 裁剪任务栏区域均不能消除该现象；只有让 HWND 的实际外接矩形不进入任务栏坐标才能稳定规避。

### 5.2 窗口大小和显示器

配置坐标仍以显示器完整矩形为基准，不使用工作区，避免任务栏位置改变准星坐标。实际 HWND 和交换链只覆盖当前可见内容的包围盒，并预留抗锯齿和滤波边距。对于不相邻的准星、图像和 Toast，可使用同一显示器下的独立 HWND，避免透明空白区域形成过大的合成目标。

以显示器为单位管理小尺寸窗口的好处是：

- 每个显示器可以独立启停；
- 不会因透明空白区域覆盖任务栏而改变任务栏外观；
- 显示器或内容包围盒变化时只重建受影响的窗口和交换链；
- DPI 和渲染尺寸更容易保持一致；
- 交换链尺寸和显存占用随实际内容缩小；
- 不会因为负坐标或不同 DPI 产生虚拟桌面缩放误差。

屏幕中心内容的窗口宽高必须与目标显示器宽高保持相同奇偶性，使偶数分辨率的整数中心和奇数分辨率的半像素中心都能精确映射。内容移出屏幕时先在显示器本地坐标中计算包围盒，再与完整显示器边界相交；不能改用 `rcWork` 重新计算锚点。

显示器变化处理：

- `WM_DISPLAYCHANGE`：重新枚举显示器；
- `WM_DPICHANGED`：更新窗口像素尺寸和渲染目标；
- `WM_DEVICECHANGE`：处理显示器拔插后的资源重建；
- `EVENT_SYSTEM_FOREGROUND`：焦点屏幕模式下重新计算目标显示器。

### 5.3 渲染资源

Host 启动时创建一个支持 BGRA 的 D3D11 device。每个显示器拥有：

- 一个 composition swap chain；
- 一个 DirectComposition visual；
- 一个 D2D device context；
- 一份当前 Profile 的渲染资源；
- 一份可选 Toast 资源。

准星和静态图片不需要每帧重绘。只有以下事件触发重绘：

- Profile 或模式修改；
- 开关可见性变化；
- Toast 创建、更新或过期；
- 显示器、DPI、窗口尺寸变化；
- D3D device lost 后重建。

检测到 `DXGI_ERROR_DEVICE_REMOVED` 或 `DXGI_ERROR_DEVICE_RESET` 时，销毁所有 GPU 资源并重新创建 device、swap chain、visual 和 bitmap cache。

## 6. 多显示器和焦点屏幕

### 6.1 显示器标识

不能把 `HMONITOR` 或枚举顺序直接存入配置。显示器重启、拔插或主屏切换后这些值可能变化。

运行时使用：

- `EnumDisplayMonitors` 和 `GetMonitorInfo` 获取几何区域；
- `MonitorFromWindow`、`MonitorFromPoint` 判断窗口或鼠标所在显示器；
- `QueryDisplayConfig` 获取显示器设备路径和拓扑信息；
- 以设备路径优先建立持久化 MonitorId，设备路径不可用时回退到名称、分辨率和位置组合。

### 6.2 焦点屏幕规则

焦点屏幕模式采用以下顺序：

1. 获取当前前台窗口；
2. 用 `MonitorFromWindow` 获取前台窗口所在显示器；
3. 如果前台窗口无效，使用 `GetCursorPos` 和 `MonitorFromPoint`；
4. 仅当目标 MonitorId 发生变化时切换覆盖窗口。

通过 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND, ..., WINEVENT_OUTOFCONTEXT)` 监听前台窗口变化，不能用高频轮询作为主要机制。

## 7. 输入和逻辑开关

### 7.1 按键统一表示

所有输入后端都转换成统一结构：

```text
KeyIdentity {
  device: keyboard | mouse
  code: uint16
  extended: bool
  modifiers: Ctrl | Alt | Shift | Win
}
```

键盘输入的 `code` 保存硬件扫描码，鼠标输入的 `code` 保存 Left、Right、Middle、X1、X2 的稳定枚举值。不要只保存显示名称或虚拟键值。左右 Ctrl、左右 Alt、数字区 Enter、方向键和扩展键必须保留扫描码及扩展位。

### 7.2 后端选择

- `RegisterHotKey`：带 Ctrl/Alt/Shift/Win 的非 Hold 键盘组合键。
- Raw Input：裸键、鼠标按键、长按、按键释放和重复键过滤。使用 `RegisterRawInputDevices` 注册键盘与鼠标设备，并设置 `RIDEV_INPUTSINK` 与 Host 隐藏窗口，使 Host 无焦点时仍能接收输入。
- `WH_KEYBOARD_LL` 与 `WH_MOUSE_LL`：仅作为 Raw Input 不可用时的成对回退。

同一个绑定只能由一个后端生效，避免 Raw Input 和低级钩子同时触发 Toggle 两次。

### 7.3 状态机

```text
KeyDown:
  if alreadyPressed: ignore auto-repeat
  else:
    mark pressed
    Independent: set true/false
    Toggle: invert state
    Hold: set true

KeyUp:
  mark released
  Hold: set false

DeviceLost / SessionLock / EngineShutdown:
  clear all pressed keys
  Hold switches set false
```

启动、锁屏、解锁、远程桌面切换和输入设备拔出都必须清理长按状态，防止“松开事件丢失”造成准星永久显示。

配置保存前做冲突校验：

- 同一开关的开、关键不能产生无法区分的冲突；
- 同一组中不允许多个动作绑定相同触发条件；
- 禁止系统保留组合键；
- 长按键不能同时作为同一逻辑组的 Toggle 键；
- 注册失败时向 UI 返回具体冲突键和 Win32 错误码。

## 8. 配置、资源和 IPC

### 8.1 本地配置

配置数据与应用状态分开持久化：

- 配置文档只保存准星、逻辑开关及其快捷键，以及未来的动画与动画快捷键；
- 应用状态文档保存配置集、当前选择、显示器策略、Toast 和其他全局运行设置；
- UI 偏好文档保存主题、语言和窗口状态。

图片不直接以内嵌 Base64 保存，使用独立 `assets` 目录并由图片准星通过 SHA-256 或 AssetId 引用。导出单个配置时只打包该配置及其实际引用的图片资源，不包含应用状态。

UI 拉起 Host 时通过 `--assets-root=<absolute-path>` 明确传递实例资产目录。Host 只接受简单文件名，并在规范化后确认最终路径仍位于该目录内；活动图片的文件大小和 SHA-256 必须与快照元数据一致。

写入流程：

1. UI 在内存中生成完整新快照；
2. 校验字段范围和资源引用；
3. 写入同目录临时文件；
4. Flush 文件；
5. 使用原子替换更新正式文件；
6. 保留上一份 `.bak` 文件用于恢复。

运行时热重载和磁盘落盘分开处理：IPC 应用可以按约 16 ms 合并滑块变化，磁盘保存使用约 300 ms 的防抖；程序退出、配置切换完成或防抖计时器到期时再落盘。这样不会因为连续拖动滑块产生大量文件写入，同时不延迟覆盖层更新。

Host 只读取经过 UI 校验后的文件，但仍必须进行自己的反序列化和范围校验，不能信任 IPC 或文件内容。

### 8.2 导入导出

`.epsx` 包结构：

```text
manifest.json
profiles.json
assets/
  <sha256>.png
  <sha256>.svg
```

导入必须限制：

- ZIP 总解压大小；
- 单个文件大小；
- 文件数量；
- 路径穿越；
- 重复 AssetId；
- SVG 外部引用和脚本；
- JSON 深度和数组长度。

合并规则：

- 相同 ProfileId 且内容相同：跳过；
- 相同 ProfileId 但内容不同：生成新 GUID；
- 相同名称：允许重复，但 UI 显示冲突提示；
- 缺失图片资源：整包导入失败，不产生半成品。

### 8.3 Named Pipe 协议

消息统一使用：

```json
{
  "protocolVersion": 1,
  "requestId": "guid",
  "type": "ApplySnapshot",
  "payload": {}
}
```

最低限度的消息类型：

- `Hello`
- `GetState`
- `ApplySnapshot`
- `SetActiveProfile`
- `SetSwitchState`
- `SetMonitorSelection`
- `ShowToast`
- `Ack`
- `Error`
- `HostStateChanged`

IPC 必须：

- 使用 `PIPE_REJECT_REMOTE_CLIENTS` 拒绝远程客户端；
- 使用当前用户 ACL，默认只允许当前用户访问；
- 通过随机 pipe 名、单实例互斥量和握手 token 防止其他本地进程伪造 UI；
- 限制单条消息大小；
- 每条请求带 `requestId`；
- 命令幂等或带版本号；
- UI 断开时 Host 继续使用最后一份有效快照；
- Host 正常退出前在同一用户目录原子写入实例级 PID 标记，已连接 UI 看到标记后停止重连并退出；
- Host 异常退出不写标记，UI 继续执行退避重连和拉起；下一次普通 UI 启动会清除旧的正常退出标记。

## 9. 热重载链路

以滑块调整支臂长度为例：

```text
Avalonia Slider / NumberBox
  -> 更新 ViewModel
  -> 生成 Snapshot(version=N)
  -> Named Pipe ApplySnapshot
  -> Host 校验范围
  -> 预加载/重建受影响资源
  -> 原子替换 render snapshot
  -> 下一次提交显示
  -> Ack(version=N)
```

滑块操作可以把 IPC 发送合并到约 16 ms 一个批次，但不能延迟最终显示。资源解码和纹理创建不能阻塞窗口线程；创建失败时 Host 保留旧资源并返回错误。

UI 只有在收到 `Ack` 后才将版本标记为已应用。连续修改时，旧版本可以被新版本覆盖，但不能让旧版本在新版本之后再次生效。

`HostClient.QueueSnapshotAsync` 提供 16 ms 合并入口。同一批次内所有调用等待最新版本的同一个发送结果；版本必须严格递增，旧版本不能替换已排队或已发送的新版本。需要立即确认错误的非连续操作仍可直接调用 `ApplySnapshotAsync`。

## 10. 提示和预览

### 10.1 Toast

Toast 是 Host 内的第二种渲染对象，不创建可交互的独立窗口。每条 Toast 包含：

```text
Toast {
  id
  text
  category
  createdAt
  expiresAt
  anchor
  offsetPx
  fontFamily
  fontSizePx
  color
  backgroundColor
}
```

同一开关的连续状态变化只保留最新一条提示。配置集切换提示优先级高于普通开关提示。

IPC `ShowToast` 负载包含 `id`、`deduplicationKey`、`text`、`category`，以及可选的 `priority` 和 `durationMs`。Host 对同一去重键执行替换，高优先级消息抢占当前消息，低优先级消息进入待显示队列。Toast 使用与主视觉分离的紧边界 HWND，但保持不可交互和点击穿透。

### 10.2 UI 预览

Avalonia 预览只用于编辑，不作为最终覆盖层。为了避免 Avalonia 和 C++ 两套几何公式漂移：

- 统一使用同一份 JSON 字段；
- 在 C# 和 C++ 中分别实现同样的几何纯函数；
- 为 0、90、180、270 度、负坐标、奇数宽度和高 DPI 增加 golden test；
- 最终显示位置以 Host 的物理像素计算结果为准。

定位模式默认在 Avalonia 预览中拖拽。若需要在真实屏幕上定位，进入显式“定位模式”后才临时允许定位辅助层接收鼠标；退出后立即恢复点击穿透。

## 11. 需要补充或确认的产品决策

以下内容目前需求没有足够精度，开发前必须定稿：

1. 中心点是否需要半径、形状和透明度配置。
2. 支臂是否允许独立设置 `gapPx`，还是只允许独立角度、长度和宽度。
3. 配置的默认初始状态：开关 A/B 是否都关闭。
4. 焦点屏幕按前台窗口还是鼠标所在显示器；建议提供明确的二选一模式。
5. 多显示器中“全部屏幕”是每块屏幕显示同样的本地坐标，还是只在主屏显示一次。
6. 图像超出屏幕边界时是裁剪、隐藏还是允许跨屏。
7. 用户指定字体不存在时是否回退到 Segoe UI。
8. 配置导入发生同名冲突时是否自动重命名。
9. 是否允许透明度、旋转、镜像和图像裁剪；这些会影响 ImageRenderer 数据模型。
10. 基准性能测试的 CPU 型号、显示器数量、分辨率、刷新率和 HDR 状态。

## 12. 验证计划

### 12.1 单元测试

- CrosshairGeometry：角度、间隔、长度、宽度、负坐标和半像素对齐。
- VisibilityRule：A、B 四种组合规则。
- HotkeyStateMachine：Toggle、独立开关、长按、重复键、丢失 KeyUp。
- ConfigValidator：越界值、未知字段、版本迁移和引用缺失。
- ImportMerger：GUID 冲突、同名、重复资源和失败回滚。
- CoordinateMapper：显示器边界、DPI、负虚拟坐标。

### 12.2 集成测试

- UI 与 Host 启停、重连和 Host 崩溃恢复。
- 使用 Avalonia Headless 验证主题初始化、关键页面加载、数据绑定、命令、参数范围和配置集拖放状态转换。
- 对 FluentAvalonia 的升级至少执行主窗口、颜色编辑、配置列表和确认对话框的启动冒烟测试。
- ApplySnapshot 连续版本的顺序和幂等性。
- 多显示器拔插、主屏切换和 DPI 变化。
- Raw Input 与 RegisterHotKey 不重复触发。
- 资源导入后纹理缓存和设备丢失重建。

### 12.3 覆盖矩阵

| 维度 | 最低测试组合 |
|---|---|
| 系统 | Windows 10、Windows 11 |
| 显示模式 | 窗口化、无边框、Fullscreen Optimizations |
| 图形 API | DX9、DX11、DX12、Vulkan、OpenGL |

### 12.4 首个技术原型验收

在开始完整 UI 前，先完成一个只有 Host 的原型：

1. 在两个不同 DPI 的显示器创建覆盖窗口；
2. 绘制中心点、四支臂和透明 PNG；
3. 鼠标点击、滚轮和键盘输入完全穿透；
4. 前台窗口切换时焦点屏幕跟随；
5. Raw Input 长按按下/释放状态正确；
6. 关闭 UI 后 Host 继续运行；
7. 在 DX11、DX12 无边框和 Vulkan 窗口中验证层级；
8. 记录 CPU、内存、Present 延迟和设备丢失恢复结果。

点击穿透和覆盖层级原型未通过前，不应继续堆叠配置管理和视觉功能，因为这两项决定整个 Overlay Host 的实现路线。
