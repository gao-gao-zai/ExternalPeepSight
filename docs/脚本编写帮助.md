# Lua 脚本编写帮助

本文档说明 ExternalPeepSight 当前高级显示控制使用的 Lua 脚本 API。脚本 API 版本 `1` 提供自动设置界面；版本 `2` 在保持版本 `1` 能力的基础上，允许声明受信任的设置界面布局。

## 1. 在哪里编写脚本

打开“脚本管理”，选择脚本作用域后编辑源码：

- **配置级**：只属于当前配置。
- **配置集级**：属于当前配置集。
- **全局级**：属于整个应用。

脚本源码可以保存在独立脚本库中，也可以直接挂载到当前配置、配置集或全局目标。保存到目标前，程序会先让 Host 解析并验证脚本；验证失败时，上一份有效配置继续运行。

配置级脚本只有在当前配置的显示控制模式为“高级”时才会加载。配置集级和全局级脚本可以独立启用。

## 2. 最小脚本

脚本必须返回 `eps.script { ... }`：

```lua
return eps.script {
    api_version = "1",
    on_start = function(ctx)
        ctx.visibility:set(true)
    end
}
```

顶层只允许以下字段：

| 字段 | 类型 | 作用 |
|---|---|---|
| `api_version` | string，可省略 | 脚本 API 版本；省略时为 `"1"` |
| `bindings` | table，可省略 | 声明用户可以绑定的按键槽位 |
| `settings` | table，可省略 | 声明用户可以修改的设置项 |
| `ui` | table，可省略 | API v2 的受信任设置界面声明 |
| `on_start` | function，可省略 | 脚本加载并成为活动脚本时调用 |
| `on_input` | function，可省略 | 声明的按键发生指定事件时调用 |

脚本顶层不能添加自定义字段。脚本必须返回表，不能返回函数、字符串或其他值。

## 3. 作用域和生命周期

### 3.1 配置级

配置级脚本随当前配置加载和停止。它可以：

- 控制当前准星是否允许显示；
- 切换当前配置集内的配置；
- 读取当前配置和脚本设置；
- 响应自己的按键绑定。

它不能切换配置集。

### 3.2 配置集级

配置集级脚本随当前配置集加载。它可以：

- 控制当前准星是否允许显示；
- 切换当前配置集内的配置；
- 读取当前配置集、当前配置和脚本设置；
- 响应自己的按键绑定。

它不能切换配置集。

### 3.3 全局级

全局级脚本属于应用级运行状态。它可以：

- 控制当前准星是否允许显示；
- 切换当前配置集内的配置；
- 切换配置集；
- 读取当前配置、当前配置集和脚本设置；
- 响应自己的按键绑定。

脚本作用域只决定脚本可以操作的产品对象，不会获得文件、网络、进程、窗口句柄或 Windows API 权限。

### 3.4 多个脚本同时运行

活动的全局级、配置集级和配置级脚本可以同时运行。最终显示条件是所有活动脚本都允许显示：

```text
最终显示 =
    全局级允许显示
    且 配置集级允许显示
    且 配置级允许显示
    且 当前准星内容可用
```

因此，任意一级脚本隐藏准星，其他脚本不能强制突破这一隐藏状态。

切换配置或配置集后，Host 会重建活动脚本运行时，并重新调用新活动脚本的 `on_start`。

## 4. 回调函数

### 4.1 `on_start(ctx)`

脚本加载并成为活动脚本时调用一次。适合根据脚本设置建立初始显示状态：

```lua
return eps.script {
    settings = {
        visible_at_start = {
            title = "启动时显示",
            type = "boolean",
            default = true
        }
    },
    on_start = function(ctx)
        ctx.visibility:set(ctx.settings.visible_at_start)
    end
}
```

`on_start` 不能切换配置或配置集。这样可以避免脚本加载时形成递归切换；需要响应按键切换时，应使用 `on_input`。

### 4.2 `on_input(event, ctx)`

当脚本声明的绑定发生事件时调用：

```lua
return eps.script {
    bindings = {
        toggle = {
            title = "切换显示",
            events = { "pressed" },
            default_key = {
                device = "keyboard",
                key = "N",
                modifiers = { "ctrl" }
            }
        }
    },
    on_input = function(event, ctx)
        if event.id == "toggle" and event.phase == "pressed" then
            ctx.visibility:toggle()
        end
    end
}
```

`event` 包含：

| 字段 | 值 | 说明 |
|---|---|---|
| `event.id` | 绑定槽位 ID | 脚本声明的稳定标识符 |
| `event.phase` | `"pressed"` 或 `"released"` | 按下或松开 |

脚本只收到绑定槽位 ID，不会收到用户实际选择的键盘键或鼠标键。

## 5. 上下文 API

### 5.1 显示控制

```lua
ctx.visibility:set(true)
ctx.visibility:set(false)
ctx.visibility:toggle()
```

- `set(value)`：设置当前脚本的显示许可，参数必须是布尔值。
- `toggle()`：切换当前脚本的显示许可。

这是脚本自己的显示许可，不是直接操作渲染窗口。最终显示仍会经过其他活动脚本和内容可用性判断。

### 5.2 当前配置

```lua
local current_profile_id = ctx.profile.id

ctx.profile:switch("profile-id")
ctx.profile:previous()
ctx.profile:next()
```

- `id`：当前配置的稳定 ID，只读。
- `switch(id)`：切换到指定配置。
- `previous()`：按配置文件中的稳定顺序切换到上一个配置，首项和末项会循环。
- `next()`：按稳定顺序切换到下一个配置，末项和首项会循环。

显式切换的目标必须属于当前活动配置集。

### 5.3 当前配置集

```lua
local current_profile_set_id = ctx.profile_set.id

ctx.profile_set:switch("profile-set-id")
ctx.profile_set:previous()
ctx.profile_set:next()
```

- `id`：当前配置集的稳定 ID，只读。
- `switch(id)`：切换到指定配置集。
- `previous()`：切换到上一个配置集并循环。
- `next()`：切换到下一个配置集并循环。

只有全局级脚本可以调用 `ctx.profile_set:switch`、`previous` 和 `next`。配置级或配置集级脚本调用这些方法会失败。

### 5.4 脚本设置

```lua
local enabled = ctx.settings.enabled
local opacity = ctx.settings.opacity
```

设置值来自 UI 中保存的用户值。如果用户还没有修改过设置，则使用声明中的 `default`。设置表中的字段名就是设置 ID。

## 6. 声明按键绑定

绑定声明使用“槽位”模型：脚本声明槽位，用户在 UI 中为槽位选择具体的键盘键、鼠标键或组合键。

```lua
return eps.script {
    bindings = {
        toggle = {
            title = "切换显示",
            events = { "pressed", "released" },
            enabled = true,
            default_key = {
                device = "keyboard",
                key = "N",
                modifiers = { "ctrl" }
            }
        },
        next_profile = {
            title = "下一个配置",
            events = { "pressed" },
            default_key = {
                device = "mouse",
                key = "x1"
            }
        }
    }
}
```

字段规则：

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | 否 | `bindings` 的键名就是 ID；必须以 ASCII 字母开头，后续只能使用 ASCII 字母、数字、`_`、`-`，最长 64 字节 |
| `title` | 是 | UI 显示名称，不能为空，最长 100 字节 |
| `events` | 是 | 包含 `"pressed"`、`"released"` 中的一个或两个，不可重复 |
| `enabled` | 否 | 是否默认启用，默认值为 `true` |
| `default_key` | 否 | 新槽位首次出现时采用的默认物理按键；用户修改或清空后不再由脚本覆盖 |

绑定最多 64 个。用户选择的物理按键由 UI 保存，脚本不能读取或动态修改该物理按键。

`default_key` 使用结构化声明：

```lua
default_key = {
    device = "keyboard",
    key = "N",
    modifiers = { "ctrl", "shift" }
}
```

字段规则：

| 字段 | 必填 | 规则 |
|---|---|---|
| `device` | 是 | `"keyboard"` 或 `"mouse"` |
| `key` | 是 | 不区分大小写的受支持键名 |
| `modifiers` | 否 | `"ctrl"`、`"alt"`、`"shift"`、`"win"` 的数组，不可重复；默认无修饰键 |

键盘键名支持：

- `A` 至 `Z`、`0` 至 `9`；
- `F1` 至 `F12`；
- `Escape`、`Tab`、`Enter`、`Backspace`、`Space`；
- `Minus`、`Equal`、`BracketLeft`、`BracketRight`、`Semicolon`、`Quote`、`Backquote`、`Backslash`、`Comma`、`Period`、`Slash`；
- `Home`、`End`、`Insert`、`Delete`、`PageUp`、`PageDown`；
- `ArrowUp`、`ArrowDown`、`ArrowLeft`、`ArrowRight`；
- `NumPadEnter`、`NumPadDivide`。

鼠标键名支持 `left`、`right`、`middle`、`x1`、`x2`。

默认按键会经过与用户绑定相同的系统保留键、重复键和作用域冲突校验。首次应用脚本时如果默认按键与现有绑定冲突，整份配置会被拒绝。脚本升级后修改或移除 `default_key`，不会覆盖同一稳定 ID 已保存的用户绑定。删除槽位后再重新引入同一 ID，会被视为新槽位并重新采用当时声明的默认值。

如果绑定和基础级快捷键、其他活动脚本绑定产生冲突，整份配置会被拒绝，并继续使用上一份有效配置。

## 7. 声明脚本设置

### 7.1 布尔值

```lua
settings = {
    enabled = {
        title = "启用",
        type = "boolean",
        default = true
    }
}
```

### 7.2 整数

```lua
settings = {
    amount = {
        title = "数量",
        type = "integer",
        default = 2,
        minimum = 1,
        maximum = 5
    }
}
```

### 7.3 双精度浮点数

```lua
settings = {
    opacity = {
        title = "透明度",
        type = "double",
        default = 0.8,
        minimum = 0.0,
        maximum = 1.0
    }
}
```

### 7.4 字符串

```lua
settings = {
    label = {
        title = "名称",
        type = "string",
        default = "Default"
    }
}
```

### 7.5 枚举

```lua
settings = {
    mode = {
        title = "模式",
        type = "enum",
        default = "one",
        options = { "one", "two" }
    }
}
```

设置规则：

- 设置 ID 和绑定 ID 使用相同的命名规则，最长 64 字节。
- `title` 必填，最长 100 字节。
- `default` 必填，且必须与 `type` 匹配。
- `integer` 和 `double` 的 `minimum`、`maximum` 是包含边界。
- 数值必须是有限值，不能使用 `NaN` 或无穷大。
- `enum.options` 必填，包含 1 至 64 个非空且不重复的字符串。
- `default` 必须存在于 `options` 中。
- 字符串值最长 4096 字节。
- 设置最多 64 个。

设置值按照稳定 ID 保存。修改显示名称不会丢失用户值；新增设置使用默认值；同一 ID 修改类型会被视为不兼容。

## 8. 自定义设置界面

### 8.1 启用 API v2

未声明 `ui` 时，程序根据设置类型自动生成控件。需要控制设置顺序、分组、控件类型、说明、单位或条件显示时，必须显式使用脚本 API v2：

```lua
return eps.script {
    api_version = "2",
    settings = {
        enabled = {
            title = "启用效果",
            type = "boolean",
            default = true
        },
        opacity = {
            title = "透明度",
            type = "double",
            default = 0.8,
            minimum = 0.0,
            maximum = 1.0
        },
        mode = {
            title = "工作模式",
            type = "enum",
            default = "normal",
            options = { "normal", "hold" }
        }
    },
    ui = {
        sections = {
            {
                id = "general",
                title = "常规",
                description = "控制脚本的主要行为。",
                collapsible = true,
                default_expanded = true,
                columns = 2,
                items = {
                    {
                        setting = "enabled",
                        control = "switch"
                    },
                    {
                        setting = "opacity",
                        control = "slider",
                        description = "效果启用时使用的透明度。",
                        unit = "%",
                        step = 0.05,
                        visible_when = {
                            setting = "enabled",
                            equals = true
                        }
                    },
                    {
                        setting = "mode",
                        control = "segmented"
                    }
                }
            }
        }
    }
}
```

`ui` 只描述设置编辑器的布局和表现，不会创建新的设置。每个 `setting` 必须先在顶层 `settings` 中声明。

### 8.2 分区字段

`ui.sections` 是按显示顺序排列的数组，最多 16 个分区。

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | 是 | 稳定标识符；规则与设置 ID 相同 |
| `title` | 是 | 分区标题，最长 100 字节 |
| `description` | 否 | 分区说明，最长 300 字节 |
| `collapsible` | 否 | 是否允许折叠，默认 `false` |
| `default_expanded` | 否 | 可折叠分区的初始展开状态，默认 `true` |
| `columns` | 否 | 设置项列数，只能为 `1` 或 `2`，默认 `1` |
| `items` | 是 | 分区内的设置项，至少 1 个 |

所有分区合计最多包含 64 个设置项。自定义界面必须把脚本声明的每个设置恰好引用一次；遗漏、重复或引用不存在的设置都会使整份脚本验证失败。

### 8.3 设置项字段

| 字段 | 必填 | 规则 |
|---|---|---|
| `setting` | 是 | 被显示设置的稳定 ID |
| `control` | 否 | 白名单控件类型，默认 `"auto"` |
| `description` | 否 | 设置说明，最长 300 字节 |
| `unit` | 否 | 数值单位后缀，最长 32 字节 |
| `step` | 否 | 数值控件的正有限步长 |
| `visible_when` | 否 | 单一设置值相等时显示该项 |

支持的控件：

| `control` | 允许的设置类型 | 说明 |
|---|---|---|
| `"auto"` | 任意 | 根据设置类型自动选择 |
| `"switch"` | `boolean` | 开关 |
| `"checkbox"` | `boolean` | 复选框 |
| `"slider"` | `integer`、`double` | 滑块和数值输入；设置必须同时声明上下限 |
| `"number"` | `integer`、`double` | 数值输入 |
| `"textbox"` | `string` | 单行文本输入 |
| `"select"` | `enum` | 下拉选择 |
| `"segmented"` | `enum` | 分段选择；枚举最多 8 个选项 |

`auto` 对布尔、数值、字符串和枚举分别生成开关、数值输入、文本框和下拉选择。`step` 只能用于 `auto`、`slider` 或 `number` 对应的数值设置。

### 8.4 条件显示

`visible_when` 只支持对另一个设置执行一次相等比较：

```lua
visible_when = {
    setting = "enabled",
    equals = true
}
```

`equals` 的类型必须与被判断设置一致，并满足其范围或枚举选项约束。设置项不能以自身作为显示条件。条件只影响控件是否显示，不修改、不清空设置值，也不影响脚本通过 `ctx.settings` 读取该值。

### 8.5 安全边界

自定义界面采用声明式白名单，不允许脚本提供或执行：

- AXAML、Avalonia 样式、控件模板或数据模板；
- C# 类型、任意 Avalonia 控件或事件处理器；
- 资源路径、文件路径、网络地址或动态程序集；
- 在 UI 进程中运行的 Lua 回调；
- 覆盖应用导航、脚本管理、按键冲突提示或其他系统控件的布局。

Host 会解析并规范化 UI 声明，配置中持久化的声明必须与源码重新解析出的结果完全一致。手工修改配置中的 UI 元数据会导致 Host 拒绝整份配置，并继续使用上一份有效配置。

## 9. 完整示例

下面的脚本提供一个显示开关和一个切换配置按键：

```lua
return eps.script {
    bindings = {
        toggle = {
            title = "切换准星",
            events = { "pressed" },
            enabled = true,
            default_key = {
                device = "keyboard",
                key = "N"
            }
        },
        next_profile = {
            title = "下一个配置",
            events = { "pressed" },
            enabled = true,
            default_key = {
                device = "mouse",
                key = "x1"
            }
        }
    },
    settings = {
        enabled = {
            title = "初始显示",
            type = "boolean",
            default = true
        }
    },
    on_start = function(ctx)
        ctx.visibility:set(ctx.settings.enabled)
    end,
    on_input = function(event, ctx)
        if event.phase ~= "pressed" then
            return
        end

        if event.id == "toggle" then
            ctx.visibility:toggle()
        elseif event.id == "next_profile" then
            ctx.profile:next()
        end
    end
}
```

下面的脚本可以切换配置集，因此只能挂载为全局级脚本：

```lua
return eps.script {
    bindings = {
        next_set = {
            title = "下一个配置集",
            events = { "pressed" }
        }
    },
    on_input = function(event, ctx)
        if event.id == "next_set" and event.phase == "pressed" then
            ctx.profile_set:next()
        end
    end
}
```

## 10. 沙箱和资源限制

脚本在受限的 Lua 5.4.8 环境中运行。可用标准库包括基础库的受限部分，以及：

- `table`
- `string`
- `math`
- `utf8`

以下能力不可用：

- 文件系统、网络、进程、注册表和动态库；
- Windows API、窗口句柄、渲染对象和 IPC 对象；
- `io`、`os`、`package`、`debug`；
- `collectgarbage`、`dofile`、`load`、`loadfile`；
- `getmetatable`、`setmetatable`、`rawget`、`rawset`；
- 二进制 Lua chunk。

当前限制：

- 单次执行最多约 100,000 条指令；
- 单次执行约 10 ms；
- 每个脚本 Lua 状态最多使用 4 MiB 内存；
- 脚本源码最大 256 KiB。

限制用于保护 Host。脚本不能依靠后台循环、轮询或等待来维持状态。

## 11. 验证和错误处理

建议按以下顺序测试：

1. 先在脚本管理中编辑源码。
2. 点击“验证并应用”。
3. 根据错误消息修复语法、声明或运行时问题。
4. 在绑定设置中为每个槽位选择键盘键或鼠标键。
5. 在脚本注册的设置项中填写值。
6. 使用准星编辑中的“高级”区域确认脚本注册内容。

脚本源码会经过 UI 和 Host 两次校验。常见失败原因包括：

- 没有返回 `eps.script { ... }`；
- 使用了未声明的顶层字段；
- 绑定或设置声明缺少必填字段；
- ID 重复或格式不合法；
- 设置默认值、范围或枚举选项不合法；
- API v1 脚本声明了 `ui`；
- 自定义界面遗漏、重复或错误引用设置；
- 自定义控件与设置类型不兼容；
- 脚本运行超时、超出指令限制或超出内存限制；
- 脚本作用域调用了无权限的配置集 API；
- 已保存的绑定/设置声明与当前源码不一致；
- 活动脚本的物理按键发生冲突。

校验或热重载失败时，Host 保留上一份有效配置，不会部分应用新配置。回调运行失败时，该次回调尚未提交的显示和切换命令会被丢弃，上一状态继续保留。

## 12. 当前未提供的能力

当前版本暂不提供：

- 定时器、后台线程和轮询回调；
- 设置变化回调；
- 任意系统事件回调；
- 读取实际物理键；
- 动态注册未声明的按键；
- 运行时创建持久化设置；
- 在 `on_start` 中切换配置或配置集；
- 配置级、配置集级脚本切换配置集；
- 通过脚本执行任意 AXAML、样式、模板或 Avalonia 控件代码；
- 由脚本重排应用导航、脚本管理和按键绑定等系统界面；
- 直接控制渲染窗口、透明度、图形资源或显示器。

需要这些能力时，应先扩展脚本 API 和对应的权限、生命周期、资源限制及测试契约，不能通过访问 Lua 全局对象或绕过 UI 校验实现。
