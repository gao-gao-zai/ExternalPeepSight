# 阶段 3 Host 基础设施验证记录

## 1. 完成范围

阶段 3 已将阶段 1 覆盖原型改造成具备明确线程、状态发布、显示器身份、资源恢复和诊断边界的 Host 基础设施。

- Window 线程拥有消息循环、控制窗口、覆盖 HWND 和 WinEvent Hook；
- Render 线程独占 COM、D3D11、DXGI、Direct2D、WIC 和 DirectComposition 资源；
- Input 与 IPC 线程建立可停止、可 `join`、可传播异常的生命周期骨架；
- `ThreadAffinity` 对 Window 和 Render 资源访问执行线程亲和性检查；
- `AtomicHostSnapshot` 使用 `std::atomic<std::shared_ptr<const HostSnapshot>>` 发布完整不可变快照；
- 快照版本严格单调，旧版本、空快照、重复 MonitorId 和非法显示器范围会被拒绝；
- `MonitorDescriptor` 同时保留进程内 `HMONITOR`、物理像素范围、GDI 名称、DisplayConfig 设备路径和持久化 `MonitorId`；
- `MonitorId` 优先基于 DisplayConfig target path，缺失时回退到规范化 GDI 名称；
- 显示器重建按“Render 释放 Surface、Window 销毁 HWND、Window 创建 HWND、Render 创建 Surface”的顺序执行；
- Device Lost 状态机强制执行 release、recreate、ready 顺序，并在一次恢复失败后进入 failed；
- Win32 和 HRESULT 异常保留原始错误域及错误码；
- Host 诊断输出改为单行结构化 JSON；
- 静止状态只保留初始 Present，不启动连续渲染循环。

阶段 4 和阶段 5 将在现有 IPC、Input 线程骨架中分别加入 Named Pipe 与全局输入实现。本阶段不提前实现协议传输或热键状态机。

## 2. 线程与所有权

| 线程 | 当前职责 | 主要所有权 |
|---|---|---|
| Window | 消息循环、显示器枚举、可见性、Topmost、窗口重建 | controller HWND、overlay HWND、WinEvent Hook、定时器 |
| Render | 事件驱动的 Surface 重建和绘制、Device Lost 恢复 | COM apartment、D3D11、DXGI、D2D、WIC、DirectComposition、swap chain |
| Input | 等待停止的生命周期骨架 | 阶段 5 输入后端 |
| IPC | 等待停止的生命周期骨架 | 阶段 4 Named Pipe 服务 |

Window 线程通过同步 Render 请求保证 HWND 销毁前对应的 DirectComposition target 和 swap chain 已释放。Render 请求同时携带期望快照版本；Render 线程只处理与当前原子快照版本一致的请求，避免窗口目标与配置状态错配。

## 3. 自动化测试

新增原生测试覆盖：

- 非法和旧版本快照拒绝；
- 并发发布和读取时只观察完整快照；
- Worker 启动、重复停止、重复 `join` 和异常传播；
- 跨线程调用的亲和性拒绝；
- MonitorId 大小写规范化、设备路径优先和位置变化稳定性；
- Device Lost 恢复顺序；
- 结构化诊断 JSON 转义和 HRESULT 保留；
- Host 焦点屏模式与全部屏幕模式启动、运行和退出；
- CSV 连续样本的 Present 数量不增长。

当前双屏环境中，焦点屏模式和全部屏幕模式均创建 2 个渲染 Surface，总 Present 数为 2。约 1.5 秒 smoke test 的后续采样仍为 2，证明无显示器变化和配置变化时不会持续提交相同画面。

## 5. 阶段退出结论

阶段 3 自动化退出标准已经满足：

- Host 可以独立启动、运行并正常退出；
- Render 资源在 HWND 销毁前释放，ASan 未发现生命周期错误；

- `/analyze`、ASan 和 CTest 全部通过。
